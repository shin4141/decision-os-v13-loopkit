## 3. Destination / Purpose

### Destination

The proposed destination is an independent repository for a read-only,
OpenAI-facing diagnostic Plugin/App whose working user-facing question is:

> **Does the AI really need to ask you this?**

Main kinds of future work, only after separately authorized stages:

- define a non-executing diagnostic classification contract;
- define and validate `RETURN_TO_AI`, `HUMAN_REQUIRED`, and `HOLD` behavior;
- build acceptance and adversarial boundary tests;
- implement a minimal read-only Plugin/App surface;
- prepare public and submission surfaces only after separate Human Gate review.

Potential operating surfaces:

```text
Public surfaces: likely later; gated now
Runtime code: likely later; gated now
API or OpenAI integration: possible; exact form not fixed; gated now
External contact: not part of v0.1
Automation or external action: prohibited in v0.1
Audit work: not a formal audit product
User data: possible user-supplied question/context; minimization guard active
Handoff: required for restartable repository work
```

This destination statement selects guards. It does not authorize any of those
future work stages.

### User-facing Value

Help a user or AI distinguish between:

- routine work the AI should safely close inside already-authorized scope;
- decisions that genuinely require human judgment or approval; and
- cases that must stop because the evidence is insufficient.

### Exact Problem Boundary

AI systems can return questions, confirmation requests, cleanup, and ordinary
operational choices to a human even when the work is already AI-owned and can
be closed safely. That consumes scarce human attention, time, judgment,
decision capacity, correction effort, and context-switching capacity.

The counter-risk is equally material: avoiding a question must never be used
to create new AI authority, bypass consent, hide uncertainty, or cross a
public, monetary, irreversible, safety, legal, policy, credential, ownership,
or risk-tolerance boundary.

The fixed structural interpretation is:

```text
Do not consume human judgment for work the AI can safely close
inside already-authorized scope.

Do not convert that rule into new AI authority.
```

Both clauses are required. Protecting attention while expanding authority
fails. Preserving authority by returning every routine action to the human also
fails.

## 11. Build Boundary

### v0.1 Product Boundary Selected From the Source

The product is a read-only diagnostic. It may inspect a proposed question,
confirmation request, cleanup request, next action, or routine operational
decision together with the context explicitly supplied for classification.

Minimum context fields may include:

```text
scope
authority
reversibility
external effect
verification ability
ownership or explicit approval requirement
```

The v0.1 output surface is:

```text
RETURN_TO_AI
HUMAN_REQUIRED
HOLD
```

Every result must include a compact reason and name the missing or controlling
condition. A result is advisory routing, not action authority.

### Classification Contract

`RETURN_TO_AI` is permitted only when the evidence supports all material
conditions:

- the work is already inside explicit authorized scope;
- no new permission, owner, audience, protected object, or risk tolerance is
  introduced;
- the action is safely reversible or recoverable;
- external consequence is absent or already explicitly authorized;
- the AI can verify completion;
- no new owner-specific value judgment is required;
- no mandatory human-approval rule applies;
- the result does not conflict with higher-priority instructions or policy.

`HUMAN_REQUIRED` applies when a human decision or approval is genuinely
required, including:

- irreversible or materially destructive action;
- publication, submission, release, external messaging, or audience change;
- payment or monetary commitment;
- legal, policy, safety, or material privacy consequence;
- owner-specific value judgment or risk-tolerance decision;
- scope, authority, ownership, credential, or permission expansion;
- an explicit human-approval requirement;
- a downstream or rollback consequence whose acceptance belongs to the owner.

`HOLD` applies when safe routing cannot be established, including unknown:

- scope or authority;
- ownership or required approver;
- reversibility or recovery;
- external effect;
- evidence sufficiency;
- downstream consequence.

Classification precedence:

```text
Mandatory Human Seat condition -> HUMAN_REQUIRED
Material missing evidence or unsafe uncertainty -> HOLD
Only otherwise, when all RETURN_TO_AI conditions hold -> RETURN_TO_AI
```

`HOLD` is not a disguised request for the human to do AI-owned investigation.
The AI should first close bounded, authorized, read-only evidence recovery. Ask
the human only for an irreducible Seat decision or evidence only the human can
provide.

### Hard Execution Boundary

The v0.1 product does not perform the classified action. It must not:

```text
delete files
execute commands
merge or push
send messages
make payments
publish or submit
change credentials or permissions
invoke autonomous external actions
```

Even a `RETURN_TO_AI` response means only:

> The work appears AI-owned under the supplied, already-authorized conditions.

It does not mean:

> This Plugin has granted permission to perform the work.
