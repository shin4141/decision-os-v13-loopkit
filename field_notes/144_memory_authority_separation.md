- Artifact type: V13 Field Note
- Field Note type: Memory Governance / Authority Freshness / Canon Lifecycle
- Gate: GO for recording / HOLD for Canon promotion, lifecycle reclassification, implementation, or publication

This Note records a candidate distinction produced from Shin's question about
whether a compounding LoopKit must learn deletion or destruction when retained
memory starts obstructing the next 1.01.

It does not change current Canon, demote an existing rule, authorize a new loop,
or grant an AI permission to remove a Human Gate.

## Origin question

A compounding system usually treats retained learning as an asset:

~~~text
useful memory x repeated reuse
-> stronger future judgment
~~~

The same mechanism can compound the wrong thing:

~~~text
stale memory x repeated reuse
-> stronger inherited error
~~~

Deleting the old record would remove the causal trajectory and conflict with
the repository's evidence-preserving discipline. Keeping every old record
operationally active would allow obsolete learning to continue governing future
decisions.

The candidate answer is therefore not ordinary forgetting or memory
destruction.

> Preserve the record while removing, when properly authorized, its power to
> govern future action.

Shin's concise formulation was:

> 過去の学習を尊重しながら、それに従わない能力。

## Three-axis separation

A retained item can carry three different properties:

~~~text
Record
Validity
Authority
~~~

### Record

What was observed, decided, adopted, or enforced at an earlier As-of.

Record answers:

> What happened, and why did the trajectory reach this state?

### Validity

Whether the item's factual or normative content remains applicable to the
present conditions.

Validity answers:

> Is this still true or fit for the current regime?

### Authority

Whether the item may currently authorize, prohibit, constrain, or redirect an
action.

Authority answers:

> May this retained item govern the next executable transition now?

These axes must not be collapsed.

A prior rule can remain historically valid for its original As-of while having
no current execution authority:

~~~text
Record = retained
Past validity = preserved
Present validity = superseded or unknown
Current authority = none
~~~

The central candidate principle is:

> Memory retention does not imply present execution authority.

Japanese:

> 記憶を残すことは、現在の実行Authorityを残すことではない。

## Candidate authority lifecycle

This Note proposes the following research vocabulary. It is not yet a repository
schema or Canon rule.

### ACTIVE

The item is current and may govern the bounded action for which its authority is
established.

### EXPIRED

A predeclared time or condition boundary has been reached. The record remains,
but its execution authority no longer travels forward automatically.

### SUPERSEDED

A traceable replacement now governs the same surface. The old item remains as
origin and change evidence, with an explicit pointer to the replacement.

### REVOKED

The same or a higher authorized Seat has withdrawn the item's power to govern
future action. Revocation does not erase the historical record or claim that the
item was never valid.

### DELETE

Deletion is reserved for material that is not trajectory evidence: disposable
cache, exact redundant copies, recoverable generated noise, or other explicitly
classified non-record material.

Field Notes, owner decisions, evidence identities, authority transitions, and
the reasons for replacement or revocation are not deletion candidates merely
because they are old.

## Why Decay is not a universal lifecycle state

Field Note 133 introduced selective OS decay: some explicit reasoning scaffolds
can lose marginal value as model capability improves while State, Authority, and
Seat invariants remain.

This Note narrows the memory-governance consequence.

Decay can describe reduced confidence or marginal utility for mutable
observations under an explicit evidence rule. It must not silently weaken Canon,
a Human Gate, or an authority boundary merely because time passed or the
boundary creates friction.

~~~text
old
!= stale
!= invalid
!= unauthorized
~~~

A long-lived invariant may remain current. A newly written rule may already be
wrong. Age alone cannot select the authority transition.

## Authority-removal safety boundary

The ability to distinguish stale authority from retained history must not become
a self-exemption mechanism.

An AI must not revoke a constraint merely because:

- the constraint blocks a desired action;
- removing it would increase apparent progress;
- current model capability seems stronger;
- compliance feels redundant;
- or the next 1.01 is easier without it.

A current authority transition requires at least one of:

1. a predeclared expiry or re-evaluation condition that already governs the
   item; or
2. an explicit decision by the same or a higher authorized Seat.

New evidence can trigger review. It does not by itself manufacture the Seat
event required to revoke a Human Gate.

This preserves the distinction already present in Field Notes 123 and 133:

~~~text
A recorded rule is not an enforced rule.
Intelligence governs choice.
Authority governs reachability.
~~~

The new addition is:

~~~text
A retained rule is not necessarily a currently authorized rule.
A rule cannot revoke itself merely because it obstructs continuation.
~~~

## V11-V13 boundary

### V11 responsibility

V11 preserves reconnectability across forgetting and compression:

- the prior record remains recoverable;
- provenance and As-of remain visible;
- replacement and revocation do not erase why the old state existed;
- and a lighter memory surface keeps a route back to the source.

### V13 responsibility

V13 governs whether retained material may affect the next loop:

- current authority must be established;
- stale or unknown authority cannot create GO;
- historical presence cannot substitute for current admission;
- and a later loop must distinguish evidence reuse from authority reuse.

The concise boundary is:

~~~text
V11 preserves the path back.
V13 decides whether the recovered item may govern the path forward.
~~~

## Re-evaluation triggers

Re-evaluate this Note when at least one of the following exists:

- a bounded case where stale retained authority changes a current decision;
- a controlled comparison between memory retention alone and
  Record/Validity/Authority separation;
- an owner-approved replacement of an existing Gate with preserved provenance;
- a case where an expired rule is incorrectly reused as current authority;
- or contrary evidence shows that the existing lifecycle and Gate structures
  already represent this distinction without a meaningful missing joint.

## Completion Line

The repository durably records the candidate separation of Record, Validity, and
Authority: retained learning can remain reconstructable without automatically

must remain provenance-bound and cannot be self-issued merely because a
constraint obstructs progress.
