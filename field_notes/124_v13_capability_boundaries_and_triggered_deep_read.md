## Purpose

V13 has strong documentary, handoff, branch, ownership, and pre-output governance.

It does not yet provide independently enforceable runtime behavior for every future route.

The limits below are `PARKED Integrity Gaps`, not an ordered technical-debt list or automatic maintenance queue. They activate only when a selected Forward Destination makes one unavoidable.

## Original Observation Compression

The original four observations are preserved as three gaps:

1. low-level implementation correctness still partly depends on execution-agent self-report and inspection → Integrity Gap A;
2. Guard, rollback, and context-health signals are not mechanically enforced across every runtime path → Integrity Gap B;
3. high branch-density overload or failure still partly depends on Decision Owner discomfort or anomaly detection → Integrity Gap C;
4. strong handoff and Canon surfaces do not guarantee runtime obedience → also Integrity Gap B.

The two runtime-compliance observations share one causal boundary and do not become separate active branches.

## Integrity Gap A — Independent Verification Gap

### Gap

Lower-layer implementation correctness cannot yet be verified fully independently of the execution AI that produced or reported the work.

### Future Route It May Unlock

- higher-impact implementation;
- external deployment;
- stronger audit claims;
- operation where execution-agent self-report is insufficient.

### Current Dependency

- Codex inspection and reporting;
- repository-native tests where available;
- human anomaly detection for residual mismatch.

### Activation Trigger

- implementation becomes externally used;
- low-level correctness becomes safety-critical;
- execution report and actual state diverge;
- release or delegation requires independent evidence.

### Required Evidence

- verification by an independent mechanism, model, test surface, or reproducible evidence path;
- explicit separation between execution authority and verification authority.

### Last Valid Checkpoint

Use repository-native tests, explicit inspected/unverified/`UNKNOWN` boundaries, agent inspection, and human anomaly detection. Keep higher-impact routes `HOLD` when those surfaces are insufficient.

No verifier design or implementation is authorized by this note.

## Integrity Gap B — Runtime Enforcement Gap

### Gap

A rule may exist in Canon, Field Notes, handoff, or a pre-output contract while still failing to constrain runtime generation or execution.

This gap combines:

- Guard / rollback / context-health rules not being mechanically enforced everywhere;
- handoff and Canon existing without guaranteed runtime compliance.

### Future Route It May Unlock

- unattended operation;
- longer agent chains;
- automatic loops;
- broader delegated authority;
- lower human supervision.

### Current Dependency

- model compliance;
- pre-output self-evaluation;
- canonical handoff;
- `Active Branch / Next Authorized Action` contract;
- human detection when the contract is not obeyed.

### Activation Trigger

- automation or unattended operation is proposed;
- documented rule violations recur materially;
- execution authority expands without direct human review;
- external users rely on runtime compliance.

### Required Evidence

- operational proof that prohibited output or action is blocked independently of voluntary model compliance;
- rollback and stop authority remain recoverable.

### Last Valid Checkpoint

Use the documented Canon/handoff/pre-output contract under direct review, retain explicit stop authority, and keep unattended or automatically delegated execution `HOLD`.

Runtime hooks, validators, generation blockers, MCP, plugins, and automation remain `HOLD`.

## Integrity Gap C — Branch-Density Observability Gap

### Gap

V13 does not yet have an independently reliable way to detect when branch count, branch interaction, context loading, or ownership overlap is approaching an unsafe operating limit.

### Future Route It May Unlock

- safe multi-branch operation;
- larger parallel workflows;
- earlier `CAP`, compression, or handoff;
- reduced dependence on Decision Owner discomfort signals.

### Current Dependency

- Decision Owner anomaly or overload detection;
- branch-state reporting;
- context-health interpretation;
- manual stopping and reconstruction.

### Activation Trigger

- branch density materially increases;
- branch confusion or ownership collision recurs;
- the Decision Owner must stop or reconstruct multiple active paths;
- a future route requires parallel autonomous execution.

### Required Evidence

- observable signals that detect unsafe density before human overload;
- tested `CAP`, compression, handoff, or rollback response;
- no false claim that branch count alone determines overload.

### Last Valid Checkpoint

Use one bounded active branch, explicit ownership and next action, context-health interpretation, and manual stop/handoff. Keep dense parallel autonomous routes `HOLD`.

No branch-density metric or detector is designed by this note.

## Parked Capability Boundary Rule

Each Integrity Gap preserves:

- Gap;
- future route it may unlock;
- current dependency;
- activation trigger;
- required evidence;
- last valid checkpoint.

These gaps are not ordered debts and must not auto-activate.

An Integrity Gap becomes a Forward Gap only when:

1. closing it opens an important route that is currently unavailable;
2. it is an unavoidable condition for that route;
3. the constraint or failure has evidence;
4. the work can preserve Carrier, Returnability, and stop authority.

Otherwise it remains `PARKED`.

Use this distinction:

```text
Reach Gap:
creates a new reachable route or evidence path

Integrity Gap:
makes a farther route safe enough to become reachable
```

Both may serve Aspire-Gap Compounding. Integrity work must name the specific Forward Route it unlocks.

## Field Notes as Operational Deep Memory

Field Notes are not merely historical commentary.

They preserve:

- causal provenance;
- incidents that generated Guards;
- rejected alternatives;
- rationale for current constraints;
- Forward-only deltas;
- re-entry and activation conditions;
- evidence that cannot be safely reconstructed from a short summary.

Principle:

> The thin surface enables entry. Relevant Field Notes enable inheritance of operating judgment.

### Human / First-Time Surface

A first-time user should be able to begin from:

- README or an ordinary repository entry;
- `AGENTS.md` or equivalent authority surface;
- canonical current handoff.

The human does not need to read the full Field Note corpus before using the repository.

### AI Fork / Operational Deep-Read Surface

An AI must read the relevant Field Notes before proposing or executing a change when it is:

- forking the operating structure;
- modifying governance;
- changing branch, handoff, gate, rollback, context-health, or authority rules;
- investigating a repeated failure;
- continuing work whose rationale is stored in Field Notes.

### Triggered Deep-Read

1. identify the active branch or proposed operational change;
2. locate the Field Notes directly relevant to that branch, rule family, incident, or capability boundary;
3. read those notes before changing the operational contract.

Do not require every AI to load every Field Note for every task.

Do not flatten Field Note rationale into a short summary when the causal path can affect the current decision.

A Field Note does not authorize execution. `Active Branch`, `Next Authorized Action`, `Current Gate`, and canonical authority continue to control action.
