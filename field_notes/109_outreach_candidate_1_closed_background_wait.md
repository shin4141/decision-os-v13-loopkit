# Field Note 109 — Outreach Candidate 1 Closed as Background Wait

## Layer

V13 / Outreach Pilot / Background Wait Discipline

Adjacent layers:

- V12 Completion Integrity / closure of external dependency

## Summary

Outreach Pilot Candidate 1 clarified an important V13 wait-state rule:

```text
A response window is not an attention window.
```

The original rule was to wait seven days without additional outreach or follow-up pressure.

That rule was valid as an external response window.

However, once a reply arrived, the no-response wait was superseded. The remaining calendar window should not keep the operator or the active work loop frozen.

## Candidate 1 State

Candidate 1 status:

```text
CLOSED as no-response wait.
Superseded by reply.
No additional push.
No sales follow-up.
No new outreach expansion from this candidate.
```

This means the original 7-day no-response check no longer needs to be treated as an active unresolved dependency.

## What Changed

Before reply:

```text
Candidate 1 = background no-response wait
No additional message
No expansion from this candidate
```

After reply:

```text
Candidate 1 = no-response wait superseded
Reply handling becomes a separate bounded decision
No automatic follow-up
No outreach expansion
```

## V13 Learning

The learning is:

```text
Waiting for an external response should not freeze the operator’s active work.
```

A waiting window may remain valid for evaluation, but it should not consume attention if no action is possible or useful.

In V13 terms:

```text
External response wait: background HOLD
Active work: reallocate to bounded next loop
Additional push: HOLD or CAP
```

## Resource Justice Note

If reply probability decays over time, then active waiting becomes increasingly costly.

A seven-day wait rule may protect against over-messaging, but it should not become seven days of operator inactivity.

The correct split is:

```text
Do not pressure the candidate.
Do not keep the operator’s attention parked on the candidate.
```

This preserves both outreach discipline and operator resources.

## Prevented Failure

Without this closure, the system could have continued treating Candidate 1 as an unresolved active dependency, keeping the operator’s attention tied to a response window that had already been superseded by reply.

## Future Rule

For future outreach pilots:

```text
A no-response wait is closed when either:
1. the wait expires without reply, or
2. a reply arrives and supersedes the no-response state.
```

After closure, do not keep the candidate as an active attention burden.
